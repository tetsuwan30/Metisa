# Metisa

Metisa は、共同作業のための Web アプリケーションです。

情報を整理・共有し、チームで利用するためのワークスペースを目指しています。

## アプリケーション

### Wiki

Google アカウントでログインして利用する、階層型の Wiki
アプリケーションです。 WYSIWYG
エディタを使ってページを作成・編集し、ページ同士を階層的に整理できます。

#### 主な機能

##### 1. Google アカウント認証

-   Google OAuth 2.0 / OpenID Connect を利用したログイン
-   設定ファイルで許可したメールアドレスのみアクセス可能
-   署名付きセッショントークンによるログイン状態の管理
-   ログアウト機能

##### 2. ページ管理

-   ページの新規作成・編集・削除
-   ページ ID の自動生成
-   親ページ・子ページによる階層管理
-   ページの親階層の変更
-   サイドバーでのページツリー表示
-   ページツリーの展開・折りたたみ
-   タイトルによるページ検索
-   パンくずリストによる階層表示
-   ページごとのリンク（パーマリンク）
-   ページリンクのコピー

##### 3. WYSIWYG エディタ

ブラウザ上で、次の書式やコンテンツを編集できます。

-   見出し（H1 / H2 / H3）
-   太字、斜体、下線、取り消し線
-   箇条書き、番号付きリスト
-   引用
-   コードブロック
-   URL リンク
-   Wiki 内のページへのリンク
-   Wikipedia へのリンク
-   水平罫線
-   字下げ
-   表の挿入・行列の追加・削除
-   画像のアップロードと挿入
-   画像の貼り付け、ドラッグ＆ドロップによる挿入
-   書式のクリア、元に戻す、やり直す

##### 4. ページ内の埋め込み機能

ページ本文に、動的に内容が表示される部品を挿入できます。

-   **目次**：ページ内の見出しから目次を自動生成
    -   H1 のみ
    -   H1・H2
    -   H1・H2・H3
-   **子ページ一覧**：現在のページの直下にある子ページを表示
-   **子孫ページ一覧**：下位階層のページをまとめて表示
-   **キーワード一覧**：ページタイトルに指定したキーワードを含むページを表示
    -   複数キーワードは AND 条件で検索

これらの部品は、ページを表示する際に現在のページ情報をもとに生成されます。

##### 5. ページのステータス

ページごとに、次のステータスを設定できます。

  ステータス       意味
  ---------------- ------------------
  Draft            下書き
  In review        レビュー中
  Approved         承認済み
  ステータス無し   ステータス未設定

ステータスはページ一覧にも表示されます。

##### 6. 更新履歴・差分比較

-   ページの本文またはタイトルが変更されたときに履歴を保存
-   更新者のメールアドレスと更新日時を記録
-   過去のバージョンの内容を表示
-   過去のバージョンと現在の内容の差分を表示
-   過去のバージョンを編集用に読み込み
-   1ページあたり最大100件の履歴を保持
-   内容とタイトルに変更がない場合は履歴を追加しない

##### 7. ページの削除

-   削除したページは、データディレクトリ内のゴミ箱領域へ移動
-   ページの更新履歴もあわせて移動
-   削除したページの子ページは、削除したページの親階層へ移動

##### 8. 画像管理

-   PNG / JPEG / GIF / WebP に対応
-   画像ファイルの形式をデータ内容から判定
-   画像アップロードの上限は 8 MB
-   画像はログイン済みユーザーに対して CGI 経由で配信

##### 9. 画面・操作性

-   PC・スマートフォンのブラウザに対応
-   ページ一覧サイドバーの表示・非表示
-   編集モードと閲覧モード
-   保存、保存して閲覧、編集内容の破棄
-   キーボードショートカット（Ctrl+S による保存）

## 動作環境・技術

| 項目 | 使用技術 |
|---|---|
| バックエンド | Ruby 2.6 |
| 実行方式 | CGI |
| フロントエンド | HTML / CSS / JavaScript |
| 認証 | Google OAuth 2.0 / OpenID Connect |
| データ保存 | ファイルベース |
| 設定ファイル | JSON |
| Ruby ライブラリ | Ruby 標準ライブラリ |

Ruby CGI が利用できる一般的なレンタルサーバーでの動作を想定しています。
開発・設置環境の一つとして、ロリポップ！レンタルサーバーを使用しています。

データベースや Rails などの Web
アプリケーションフレームワークは使用していません。

## インストール

### 必要なもの

-   Ruby 2.6 が利用できる環境
-   CGI が利用できる Web サーバー
-   HTTPS でアクセスできるドメイン
-   Google Cloud プロジェクトと OAuth クライアント

### 1. ファイルの配置

`index.cgi` と `config.json` を同じディレクトリに配置します。

``` text
wiki/
├── index.cgi
├── config.json
└── data/
```

`data/`
ディレクトリは、アプリケーションの起動時に存在しなければ自動作成されます。

### 2. Google OAuth の設定

Google Cloud Console で OAuth クライアント ID を作成します。
アプリケーションの利用形態に合わせて、OAuth クライアントの種類は「ウェブ
アプリケーション」を選択してください。

承認済みのリダイレクト URI に、`config.json` の `redirect_uri` と同じ
URL を登録します。

`config.json` の設定例：

``` json
{
  "google_client_id": "YOUR_GOOGLE_CLIENT_ID",
  "google_client_secret": "YOUR_GOOGLE_CLIENT_SECRET",
  "redirect_uri": "https://example.com/wiki/index.cgi?action=callback",
  "session_secret": "YOUR_RANDOM_SECRET",
  "allowed_emails": [
    "user@example.com"
  ],
  "permalink_base": "https://example.com/wiki/"
}
```

| 設定項目 | 説明 |
|---|---|
| `google_client_id` | Google OAuth クライアント ID |
| `google_client_secret` | Google OAuth クライアントシークレット |
| `redirect_uri` | OAuth 認証後の戻り先 URL |
| `session_secret` | セッション署名に使用する秘密鍵 |
| `allowed_emails` | アクセスを許可するメールアドレスの配列 |
| `permalink_base` | ページリンクのベース URL |

`permalink_base` は省略できます。省略した場合は `index.cgi?id=ページID`
形式の URL を使用します。

`session_secret`
には、推測されにくい十分に長いランダムな文字列を設定してください。
`google_client_secret` や `session_secret` を GitHub
などの公開リポジトリに登録しないでください。

### 3. パーミッションの設定

設置環境に合わせて、ファイルとディレクトリのパーミッションを設定します。

``` bash
chmod 700 index.cgi
chmod 600 config.json
chmod 705 data
```

CGI の先頭行（shebang）は、サーバー上の Ruby
のパスに合わせて変更してください。

例：

``` ruby
#!/usr/local/bin/ruby2.6
```

### 4. Wiki へのアクセス

ブラウザで次の URL にアクセスします。

``` text
https://example.com/wiki/index.cgi
```

許可された Google アカウントでログインすると、Wiki を利用できます。

## データ保存形式

Wiki
はデータベースを使用せず、ファイルシステムにページ情報を保存します。

``` text
data/
├── <page_id>.html
├── <page_id>.title
├── <page_id>.parent
├── <page_id>.status
├── images/
│   └── <image_id>.<extension>
├── history/
│   └── <page_id>/
│       ├── <revision_id>.html
│       └── <revision_id>.meta
└── trash/
```

  ファイル・ディレクトリ   内容
  ------------------------ ----------------------------
  `<page_id>.html`         ページ本文
  `<page_id>.title`        ページタイトル
  `<page_id>.parent`       親ページ ID
  `<page_id>.status`       ページのステータス
  `images/`                アップロードされた画像
  `history/`               ページの更新履歴
  `trash/`                 削除したページと関連データ

`data/` ディレクトリには、Web サーバーからの直接アクセスを拒否する
`.htaccess` を自動作成します（`.htaccess` に対応する Apache
環境の場合）。

## セキュリティ

現在の実装には、次の対策が含まれています。

-   Google アカウントによる認証
-   許可メールアドレスによるアクセス制限
-   HMAC-SHA256 によるセッション署名
-   Secure / HttpOnly 属性付き Cookie
-   OAuth の state パラメータ検証
-   POST リクエストの Origin 検証
-   保存時の HTML サニタイズ
-   画像データの形式検証
-   画像アップロードサイズの制限
-   保存ファイルへのアクセス権限設定
-   `.htaccess` によるデータディレクトリへの直接アクセス制限

**注意：** HTML
サニタイズは独自実装の簡易的なものです。公開環境や重要な情報を扱う環境で運用する場合は、セキュリティレビューを行い、必要に応じて専用ライブラリの導入などを検討してください。
